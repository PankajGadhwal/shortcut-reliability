# Reliability of Shortcut Mitigation under Spurious Correlations

ES 678 course project. This repository contains the data pipeline and training
code for a controlled study of whether shortcut-mitigation methods reliably
improve worst-group accuracy on Waterbirds as the strength of the spurious
correlation (rho) varies.

Main result

Controlled re-split of Waterbirds, ResNet-50, 3 paired seeds. Test WGA (%), mean ± s.d.; S1 selects checkpoints with group-labelled validation data, S4 with an ordinary in-distribution validation set.

Method	ρ = 0.95, S1	ρ = 0.95, S4	ρ = 0.99, S1	ρ = 0.99, S4
ERM	60.7 ± 1.0	53.6 ± 5.6	39.0 ± 3.6	31.7 ± 2.4
RWG (group reweighting)	84.7 ± 1.2	64.3 ± 2.2	67.7 ± 11.3	38.4 ± 4.9
JTT	73.9 ± 11.0	55.9 ± 4.9	41.2 ± 9.4	35.0 ± 2.1
Group DRO (η_q = 1)	73.9 ± 9.9	53.8 ± 1.6	not run	not run
DFR	88.2 ± 0.4	n/a (needs group labels)	87.8 ± 1.3	n/a

As ρ rises from 0.5 to 0.99, ERM's WGA falls from 90.2% to 39.0% while its in-distribution accuracy rises from 93.0% to 97.9%. RWG and DFR beat ERM in every seed once ρ ≥ 0.9 under S1; under S4 their gains shrink by half or more, and JTT and Group DRO become indistinguishable from ERM. Full results: results/main/summary.csv, results/figures/, and the paper appendix.

Reproducing the results

All commands run from the repository root. Reported results were produced on Ubuntu with one NVIDIA RTX 4090 (driver 570, CUDA 12.8), Python 3.11.7, PyTorch 2.11.0+cu128, torchvision 0.26.0, NumPy 2.4.6, pandas 3.1.1, scikit-learn 1.9.1, Matplotlib 3.11.2, Pillow 13.0.0 and wilds 2.0.1. Each run's exact versions, GPU and git commit are recorded in runs/<run>/env.json.

1. Environment
bash
python -m venv .venv && source .venv/bin/activate
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements.txt
python -m pip install -e .
python -m pip install --no-deps wilds outdated littleutils
python scripts/check_env.py      # must report cuda_available True
python -m pytest -q              # 33 tests

Choose the PyTorch CUDA build that your driver supports (pytorch.org, "Get Started").

2. Data
bash
python -c "from wilds import get_dataset; get_dataset(dataset='waterbirds', root_dir='data', download=True)"
sha256sum data/waterbirds_v1.0/metadata.csv
# expected: 2f023b9dc371f6fbb82c7cb810ff0f03e19c54c8055a2e37517ae7bb56644362

WILDS downloads waterbirds_v1.0 from huggingface.co/datasets/pangwei/wilds-waterbirds (revision 9df26fc8b17c3e54650b0ee634ab2d7804c638f1). The original Group DRO URL is also scripted (python scripts/download_waterbirds.py --dest data) but was unreachable from our network. Both releases have identical per-group counts, which make_splits.py and build_cache.py verify against the official numbers.

3. Splits, image cache, EDA

The split files are committed and must not be regenerated; verify them:

bash
sha256sum splits/controlled_v2.json
# expected: 5bb31f0626223c18a3f4d8e1c584914868d8289e00217de82294ff9ac257dd9b
python scripts/build_cache.py --data_root data/waterbirds_v1.0 --out_dir cache_256 --workers 16
python scripts/eda.py --cache_dir cache_256 --splits splits/controlled_v2.json --out_dir reports/eda

controlled_v2.json holds a fixed group-balanced test set (300 per group), a group-balanced validation set (100 per group), and for each of 10 data seeds and ρ ∈ {0.5, 0.8, 0.9, 0.95, 0.99} a class-balanced training set (1,200 images) and an in-distribution validation set (400). The paper uses seeds 0 to 2. The cache image array has SHA-256 starting f0b3b397117af0e2 (full hash in cache_256/manifest.json).

4. Main experiment (about 45 minutes on an RTX 4090)
bash
bash scripts/main_sweep.sh 2>&1 | tee results/main_sweep_log.txt

This trains ERM, RWG and JTT (T = 25, λ = 20) at every ρ for seeds 0 to 2, Group DRO (η_q = 1) at ρ = 0.95, and fits DFR on every ERM run. Rerunning resumes interrupted runs and skips finished ones. A single run is, for example:

bash
python scripts/train.py --cache_dir cache_256 --splits_path splits/controlled_v2.json \
    --rho 0.95 --data_seed 0 --method rwg
5. Unsealed evaluation, summary and figures
bash
python scripts/final_eval.py --runs "runs/controlled_*" --unseal --out_csv results/main/final_eval.csv
python - <<'EOF'
import pandas as pd

cols = ["test_wga", "test_id_acc", "test_mean_group_acc", "test_shortcut_gap", "test_worst_group_ece"]

bash scripts/pilot_methods.sh   # pilot at rho = 0.95 used to fix hyperparameters (validation only)

This copies the figures into paper/figures/, compiles the paper if a full TeX installation is present (it checks that the main paper, references included, ends on page 4), and writes paper/paper_source.zip. Without a full TeX installation, upload that ZIP to Overleaf (New Project, Upload Project).

Reproducibility notes
Determinism. Every source of randomness (data order, augmentation, head initialization) is seeded from the run's seed, and the training seed equals the data seed, so methods are compared on paired seeds. cuDNN runs in deterministic mode. Rerunning a configuration reproduced identical metrics at every logged step on our GPU; bitwise identity across different GPUs or library versions is not guaranteed.
Run identity. Each run directory is named by a hash of every result-affecting setting plus the SHA-256 of the split file and the image cache, so changed data or settings can never overwrite earlier results.
No test leakage. Training logs never compute test metrics. Test logits are written to runs/<run>/sealed/ and read only by scripts/final_eval.py --unseal, after checkpoints have been chosen on validation data. No preprocessing step is fit on data (fixed ImageNet normalization).
Preregistration. The design, hypotheses and selection protocols in PREREGISTRATION.md were committed to git before the controlled-split test logits were read. The only earlier unsealing was the official-split anchor, used as a pipeline check.
Deviations from the original plan. Ten data seeds were prepared but three were run for time. Hyperparameters were fixed from a pilot at ρ = 0.95 on seeds 0 to 2 using validation data only; in that pilot, weight decay 1.0 collapsed training and Group DRO with η_q = 0.01 matched RWG exactly, so the main study used weight decay 10⁻³ and η_q = 1.
Tests. tests/ checks split invariants (counts, disjointness, nesting), metric identities, augmentation geometry, resumption after interruption, and that Group DRO with η_q = 0 equals RWG and JTT with λ = 1 equals ERM bit for bit.
